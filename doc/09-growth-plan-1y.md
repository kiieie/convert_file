### 0.1 점검에서 찾은 즉시 수정 필요 문제

| # | 문제 | 영향 | 근거 |
|---|---|---|---|
| 1 | **GA4 태그가 한 페이지에 두 번 들어감** (`gtag/js` + `config` 중복) | 페이지뷰가 2배로 잡혀 **모든 지표가 부풀려짐**. 기준치를 잡기 전에 반드시 고쳐야 함 | 70개 HTML 파일 |
| 2 | **쿠키 동의(CMP) 없음** | 유럽·영국 방문자에게 AdSense를 띄우려면 Google 인증 CMP가 필요. 없으면 해당 지역 광고 수익이 제한되거나 정책 위반 | 저장소 전체에 consent 관련 코드 없음 |
| 3 | **브랜드 이름 혼재** ("ConvertFile" / "2Convert" / "2convert.org") | 검색 결과·북마크에서 브랜드 기억이 안 됨 → 재방문 저하 | `<title>`에 "ConvertFile"이 101개 파일 |
| 4 | **`img-pdf`와 `pdf` 페이지가 같은 검색어를 놓고 경쟁** ("image to pdf") | 서로 순위를 깎아먹음(키워드 잠식) | 두 페이지 title·keywords 겹침 |
| 5 | **`pdf.html` 한 페이지에 합치기·나누기·추출이 모두 들어 있음** | "merge pdf", "split pdf"는 각각 거대한 검색어인데 한 페이지로는 둘 다 상위권 불가 | `pdf.html` featureList |
| 6 | 붙여넣기(Ctrl+V) 업로드가 일부 도구에만 있음 | 23개 중 `image-loader.js`를 쓰는 14개만 지원, 안내 문구도 없음 | `js/core/image-loader.js` |
| 7 | 도구 화면에 "[Ad Zone] …" 자리표시 문구 노출 | 미완성 사이트처럼 보임 | 도구 페이지 전체 |

참고 시장 규모 (Semrush 추정, 2025년 하반기): iloveimg.com 월 약 3,500만 방문, imageresizer.com 약 750만~1,000만, tinypng.com 약 440만~500만. tinypng은 유입의 약 73%가 직접 방문(즐겨찾기·재방문)이다 → **이 분야에서 "활성 사이트"란 재방문이 많은 사이트**다.

## 1. 1년 목표와 지표

### 1.1 실측 기준치 (2026-10-24 확인)

| 출처 | 기간 | 클릭 | 노출 | CTR | 평균 순위 |
|---|---|---|---|---|---|
| Google Search Console | 최근 3개월 | 22 (월 약 7) | 383 | 5.7% | 30.7 |
| 네이버 서치어드바이저 | 최근 30일 | 5 (전월 대비 -58%) | 약 420 | 1.2% | — |

- **Google 색인: 12개 색인됨 / 24개 색인 안 됨 (이유 4개).** sitemap에는 140개 URL이 있는데 Google이 아는 페이지가 36개뿐이다 → **현재 가장 큰 병목은 콘텐츠가 아니라 색인**이다.
- 네이버 검색어 상위: "사진들 파일 묶는법", "사진 묶음 pdf", "영수증 이미지 pdf로 묶기", "gif 속도조절"(노출 37·클릭 0), "gif 변경", "당근마켓 사진 위치 삭제".
  - 실제 수요는 **"사진 여러 장을 PDF로 묶기"**, **"사진 위치정보 지우기"**, **"GIF 속도"** 쪽에 있다.
  - 노출은 되는데 클릭이 0인 이유: 한국어 제목이 검색어와 다름. 예) `ko/tools/metadata.html` 제목이 "EXIF 메이커 및 개인정보 지우개", `ko/tools/gif-speed.html`은 "... (GIF Speed) - ConvertFile".
- GA4: 중복 태그 수정(PR #3) 이후 수치부터 기준으로 쓴다.

### 1.2 목표 (실측 기준으로 재설정)

| 지표 | 현재 | 3개월 | 6개월 | 12개월 |
|---|---|---|---|---|
| Google 색인 페이지 | 12 | 80 | 130 | 200+ (신규 랜딩 포함) |
| Google 월 클릭 | 약 7 | 100 | 600 | 4,000 (도전 목표 10,000) |

신규 도메인(4.5개월)·색인 12개에서 출발하므로, 첫 3개월은 **클릭보다 색인 수**가 핵심 지표다.

### 1.3 기준치에서 나온 우선순위 조정

1. **색인 문제 해결이 1순위** — Search Console "페이지" 보고서의 색인 안 됨 이유 4개를 확인하고 이유별로 대응 (아래 0.1절 문제와 함께 1분기 최우선).
2. **한국어 제목·설명을 실제 검색어로 교체** — 노력은 작고 효과는 바로 나옴. 우선 대상: 이미지→PDF("사진 여러 장 PDF로 묶기"), EXIF 제거("사진 위치정보 삭제"), GIF 속도("GIF 속도 조절").
3. **GIF 속도 조절은 실제 한국어 수요가 있다** — GIF 신규 기능 투자는 계속 보류하되, 기존 GIF 페이지의 제목·설명 개선은 예외로 허용.

**북극성 지표: 주간 "다운로드 완료" 횟수.** 방문이 아니라 실제로 일을 끝낸 횟수를 본다.

**목표 재조정 규칙**: 6개월차에 월 클릭이 목표의 50% 미만이면 → 신규 도구 추가를 멈추고 기존 상위 20개 페이지의 제목·내용 개선에 집중한다.

## 2. 포지셔닝

> **"파일을 올리지 않는 파일 도구. 개수 제한·워터마크·가입 없음."**

경쟁사(iLovePDF, iLoveIMG, ezgif 등)는 서버에 파일을 올리고, 무료 사용에 개수·용량 제한을 둔다. 2convert는 브라우저 안에서 처리하므로:

1. **프라이버시** — 신분증, 계약서, 가족 사진 등 민감 파일에 강하다 (메시지 1순위)
2. **제한 없음** — 일괄 처리 개수 제한 없음, 대기열 없음
3. **오프라인 동작** — PWA 설치 후 인터넷 없이도 사용
4. **검증 가능** — 소스가 공개되어 있으니 "업로드 안 함"을 누구나 확인 가능 (오픈소스임을 신뢰 근거로 노출)

**브랜드는 "2convert" 하나로 통일**한다. 모든 `<title>` 끝은 `| 2convert`, 로고·OG 문구·About도 동일하게.

## 3. 핵심 전략 5가지

### 전략 1. 수요 큰 작업 중심으로 도구 재편

검색 수요는 "파일 형식"보다 **"하려는 일"** 에 몰린다.

| 우선 | 할 일 | 상태 | 이유 |
|---|---|---|---|
| A | **PDF 페이지 분리**: `pdf.html`을 합치기 / 나누기 / 페이지 추출·정리 페이지로 나눔. 기존 URL은 허브 페이지로 유지 | 기능 있음, 페이지 분리만 | 각 검색어가 거대함. 코드는 이미 있어 노력 대비 효과 최고 |
| A | **이미지→PDF 통합**: `img-pdf`를 대표 페이지로, `pdf.html`의 같은 기능은 그쪽으로 연결 | 정리 작업 | 키워드 잠식 해소 |
| A | **목표 용량으로 줄이기** (20KB, 50KB, 100KB, 200KB…) — 기존 압축 도구에 "목표 용량" 모드 추가 | 신규 기능 | 관공서·채용·시험 원서 제출 수요가 매우 큼 (특히 인도·한국) |
| A | **PDF 압축** | 신규 | PDF 분야 상위 검색어. 브라우저 처리 품질을 먼저 시험 |
| B | **증명사진·여권사진 규격 맞추기** (기존 배경 제거 + 자르기 조합) | 기존 기능 조합 | 프라이버시 강점과 잘 맞음 |
| B | **SNS 규격 리사이즈 프리셋** (인스타, 유튜브 썸네일, 카톡 프로필 등) | 기존 리사이즈에 프리셋 | 프리셋 = 고유한 도구 상태라 랜딩 가치 있음 |
| B | **PDF 서명 넣기** | 신규 | 민감 문서 → 프라이버시 강점 |
| C | HWP → PDF (한국) | 기술 검토 | 수요 매우 큼. 브라우저 처리 가능 여부 먼저 확인 (hwp.js 등) |

**축소**: GIF 5종과 밈 생성기는 유지하되 신규 투자는 멈춘다. 사이드바에서는 "GIF 도구" 하나로 묶는다. (daily planner 에이전트의 "밈/GIF 제외" 규칙과 일치)

**URL 원칙**: 이미 색인된 URL은 바꾸지 않는다. 새 페이지는 기존처럼 `/tools/<이름>.html`에 추가하고, 부득이 통합할 때는 `_redirects`에 301을 건다.

### 전략 2. "얇지 않은" 프로그램형 랜딩 페이지

키워드만 바꾼 템플릿 페이지는 2026년 기준 색인 제외 위험이 크다. 대신 **각 페이지가 실제로 다른 기본값을 가진 도구**가 되게 만든다.

| 페이지 묶음 | 예시 | 페이지마다 다른 점 |
|---|---|---|
| 형식 변환 쌍 | `/tools/png-to-jpg.html`, `/tools/heic-to-png.html` … (약 30쌍) | 입력·출력 형식이 미리 설정됨, 형식별 주의점(투명도 손실 등) |
| 목표 용량 | `/tools/compress-image-to-50kb.html` … (8~10개) | 목표 용량 미리 설정, 해당 용량이 필요한 대표 상황 |
| 규격 프리셋 | `/tools/resize-instagram-post.html`, `/tools/passport-photo-us.html` … (30~50개) | 픽셀·비율·배경색 미리 설정, 공식 규격 출처 링크 |

- **10~20개씩 묶어 배포 → 4주 뒤 Search Console에서 색인·노출 확인 → 다음 묶음.**
- **중단 기준**: 한 묶음의 60% 이상이 4주 뒤에도 "크롤링됨 – 색인 안 됨"이면 다음 묶음을 멈추고 페이지 내용을 보강한다.
- 언어 확장은 영어판에서 성과(노출 100회/월 이상)가 난 페이지만 번역한다.
- 기존 공통 JS(`js/tools/*.js`)를 그대로 쓰고 URL 쿼리나 `data-` 속성으로 기본값만 바꾼다 → 코드 중복 없이 페이지 추가.

### 전략 3. 재방문을 만드는 UX

| 기능 | 효과 | 노력 |
|---|---|---|
| **붙여넣기 업로드를 23개 도구 전부로 확대** + 업로드 영역에 "Ctrl+V로 붙여넣기" 안내 | 스크린샷 작업이 빨라짐 → 습관화 | 작음 (공통 모듈 존재) |
| **최근 사용한 도구** (홈 상단, localStorage) | 재방문 시 1클릭 | 작음 |
| **설정 기억** (마지막 품질·크기 값) | 반복 작업자 편의 | 작음 |
| 첫 화면 단순화 (진행 중인 tool-flow 롤아웃 완료) | 완료율 상승 | 중간 (스펙 있음) |
| **PWA 설치 유도 + 안드로이드 공유 대상(Share Target)** | 갤러리 → 공유 → 2convert로 바로 열기 | 중간 |
| **도구 이어서 쓰기** ("자르기 → 압축 → 다운로드"를 재업로드 없이, IndexedDB로 파일 전달) | 경쟁사 대비 확실한 차별점, 세션당 페이지 증가 | 큼 |
| 속도: 광고·분석 스크립트 지연 로딩, Google Fonts 대신 시스템 폰트 검토 | 모바일 체감 속도·Core Web Vitals | 작음 |

### 전략 4. 신뢰감 있는 콘텐츠로 교체

- 도구 하단 설명문을 **사용자 언어**로 다시 쓴다: "어떻게 쓰나요 / 왜 안전한가요 / 자주 묻는 질문" 3단 구성. 기술 용어 나열 문단은 삭제.
- 블로그는 "~하는 방법" 실용 가이드 위주로 **월 4편**. 예: "아이폰 사진이 HEIC로 저장될 때 해결법", "정부24 첨부파일 용량 줄이는 법", "PDF에서 특정 페이지만 빼는 법". 각 글은 해당 도구로 연결.
- 글마다 **실제 화면 캡처와 직접 해 본 결과**(전·후 용량 등)를 넣는다 → AI 대량 생성 글과 차별화.
- 운영자 소개(About)를 실제 운영 동기·연락처로 보강 → 신뢰도와 AdSense 심사에 도움.
- "[Ad Zone]" 문구 제거, 광고는 결과 다운로드 **아래**에만 배치 (작업 흐름을 막지 않고, 다운로드 버튼과 혼동되지 않게).

- 기존 daily 에이전트 루프(planner → architect → builder → reviewer)는 **이 문서의 분기 체크리스트에서 후보를 고르도록** planner 지침에 연결한다.
- marketer 에이전트는 매주 Search Console 상위 쿼리와 노출 대비 클릭률이 낮은 페이지를 뽑아 제목·설명 개선 제안.
- 매월 1회: 1절 지표표 업데이트, 다음 달 우선순위 조정.
- 큰 변경(페이지 분리·통합, 브랜드 변경)은 배포 후 2주간 Search Console의 색인 상태·노출을 확인한다.

## 6. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 대량 템플릿 페이지가 "저품질 대량 콘텐츠"로 판정 | 페이지마다 실제 다른 도구 기본값 + 고유 설명, 소량 묶음 배포, 2절 중단 기준 적용 |

| 신규 도메인이라 초기 성장이 느림 | 6개월차까지는 검색 외 채널(네이버·커뮤니티)과 재방문 기능으로 보완 |

| 브라우저 처리 한계 (큰 PDF·영상, 저사양 폰) | 파일 크기 안내, Web Worker 처리, 실패 시 명확한 안내 문구 |
| AdSense 정책 (광고가 다운로드 버튼과 혼동, CMP 미비) | 광고는 결과 아래·라벨 표시, 1분기에 CMP 도입 |
| 1인 운영 시간 부족 | 분기당 핵심 4개만 확정, 나머지는 에이전트 루프에 맡김 |
